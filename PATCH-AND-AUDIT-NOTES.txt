Retry/delete hotfix:
- delete_file postcondition verification is operation-aware: staged deletion is verified by original-path absence.
- FileNotFoundError after a successful staged deletion is recorded as positive deterministic verification evidence.
- Ordinary failed attempts build a deterministic FAILURE RECOVERY CHECKPOINT before parking.
- The checkpoint includes prior continuation context plus recent persisted Redis tool evidence.
- Retry parking persists the active in-memory PromptJob so the new context survives Redis park/restore.
- Recovery explicitly instructs the worker to reconcile state and resume from the first unresolved postcondition instead of replaying successful work.

Weekly/deep-history audit (behavior unchanged):
- Weekly maintenance runs only while the prompt queue/pending set is idle.
- Redis active marker records run/mode/phase and is retained on failure for resume.
- Regular mode incrementally rebuilds background memory.
- Deep mode selects old terminal history, creates a SQL backup, compresses grouped attempts, replay-validates sampled archives, then validates archives and prunes covered raw history.
- Replay-validation failure preserves raw history and retains the SQL backup.
- Successful deep maintenance rebuilds background memory and removes the temporary SQL backup.
- Audit note: deep-history replay validation samples a configurable subset before pruning all compressed groups.
- Audit note: the weekly active marker resumes at run/mode level, not as a fine-grained transactional cursor through every completed phase.
